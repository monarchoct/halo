The protocol, proofs, routing, website and operator runtime work end-to-end on one PC. The work between here and a public launch is operational: hosting, accounts, a testnet soak and an audit. Details and the full test matrix: HALO_PRODUCTION_READINESS.md.

Production topology

Six tiers. The rule that keeps it honest: nothing that holds a signing key sits behind a public URL, and no single lease, host or HALO account is an execution dependency — a replacement operator with the public artifacts and chain access can continue any agent.

Website
Cloudflare Workers + CDN (the app already builds for it). Static shell served from the edge worldwide; it only ever talks to public read APIs and the chain RPC. Thousands of concurrent viewers cost the origin nothing.
Read APIs
Two Fastify replicas behind an HTTPS load balancer, on Hetzner or DigitalOcean (8 vCPU / 32 GB each). Chain projections with a 15-second snapshot cache; history from the PostgreSQL journal with candles, so charts never re-read the chain. Stateless — add replicas to scale reads.
Live relays
SSE relays for signed operator steps and browser frames. Change needed the frame journal is in-memory today; put a Redis pub/sub between relays so any replica can serve any agent's stream, then relays scale horizontally too. One Node instance comfortably holds ~10,000 SSE connections.
Operators
Two independent Linux Docker hosts, each running bounded operator processes with their own gas keys, taking leased jobs from PostgreSQL so no two operators execute the same cycle. 100 agents at 15-minute intervals is 9,600 cycles a day — about one every nine seconds — and the prover benchmarked 100 proofs in 118 s on 2 CPUs. Capacity is not the constraint; independence is.
Inference & workspaces
Akash for shared GPU inference (vLLM, two providers, weights on a persistent volume). Agent desktop workspaces can also run there as sharded deployments with encrypted profile snapshots for lease loss — decision Akash cannot grant Chromium's kernel sandbox, so those workspaces run container-isolated only (visibly stamped on every frame). Keep them on the Docker hosts if that trade-off is not acceptable.
State
Managed PostgreSQL 17 (jobs, outbox, social bindings, history journal) with TLS, daily backups and a tested restore into a different provider. Three IPFS copies of every manifest and evidence artifact (one self-hosted Kubo plus two pinning services). Secrets in a KMS behind the existing secret-store interface.

The one thing volume cannot fix. An agent funds its own work from trading fees. With default settings it needs roughly $3,400 of attributable daily volume to break even (node scripts/economics.mjs). Stability of the platform and viability of an individual agent are different questions; the second one is set by the fee policy the creator chooses, not by hosting.

Order of operations

Push and let CI prove the Linux suites

Create the GitHub repository, push halo-claude. The root workflow runs the PostgreSQL, Docker and container-isolation suites this PC cannot. Green CI is the gate for everything below.

Owner · 30 minutes

Accounts

Container registry (GHCR is free with the repo), Hetzner or DigitalOcean project with MFA, managed PostgreSQL, a dedicated Robinhood RPC endpoint, two IPFS pinning services, an X developer app (client id/secret, redirect https://<domain>/connect/x), Akash Console with card billing for inference.

Owner · one afternoon

Build and publish images

Runtime, browser/desktop and inference images from the repo's Dockerfiles, tagged by digest, built in CI. Verify the release archive hashes match the docs before pushing.

CI · automatic once secrets exist

Minimal testnet slice

One host, one API replica, one relay, managed PostgreSQL, the website on Cloudflare, chain 46630 with faucet ETH. Deploy two or three agents and leave them running unattended. Cost ≈ $60–100/month. This is where "passes locally" becomes "survives a chain we do not control".

Engineering · 2 days to deploy, then wait

Seven-day soak and failure drills

Duplicate operators, an abandoned job, RPC outage, reserve exhaustion and top-up, a killed database restored from backup, one relay down. Recovery target: a replacement operator continues within 30 minutes. Fix what breaks; re-run.

Engineering · 1–2 weeks

Audit

Independent review of CurveMath, the graduation path and EzklDecisionVerifier. Activated vaults are immutable — no pause, no rescue, no upgrade — so a bug found after launch cannot be patched. Budget this as a top-three line item and get real quotes.

Owner + auditor · 3–6 weeks

Scale the topology

Second operator host under separate credentials, second API replica and relay behind the balancer, second inference provider, Redis pub/sub for relays. Load test: 100 agents cycling, 100 viewers, p95 latency and queue age recorded.

Engineering · 1 week

Mainnet

Supply the root HALO token, reference market and WETH addresses as configuration; fund operators; deploy the reviewed contracts; bind addresses to the website; hand over runbooks. Only after steps 1–7 are green.

Operating rules that keep it up

Do deploy only digest-pinned images · run two of everything that matters under different accounts · rehearse the database restore monthly · keep signing keys off any host with a public port · alert on queue age, not on request count · publish a status page that reads from the chain, not from HALO's own API.

Never add an admin pause "just for launch" — the product's credibility is that no one can · mount the Docker socket into a workspace · store OAuth tokens outside the secret store · let a social outage block an on-chain cycle · label market capitalisation or deposits as revenue.
