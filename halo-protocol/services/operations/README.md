# Public Operations API

`GET /v1/agents/:agent/operations?limit=20` exposes recent scheduled work, sanitized mailbox provisioning status, prepared public theses and reported social outcomes. It verifies the target registry/agent and binds the response to the configured chain. The website's Operations tab validates that binding, refreshes every 15 seconds and retains an explicitly stale snapshot during an outage.

Run the privileged installation step in `install.mjs` once against the operator's migrated PostgreSQL 17 database. It creates four projection views and a new random restricted reader. Save the returned credential directly in an operator-controlled secret file; never put it in logs or deployment JSON. Start `cli.mjs` using only that reader credential through its configured environment variable. The service rejects administrative roles and inherited table or column access to private source data. Credentials are removed from its environment after opening the pool.

The reader can select the public views and cannot mutate jobs or inspect private inbox addresses, provider identifiers, raw payloads, errors or lease-owner strings. Public job completion is labeled as an operator report; canonical financial receipts are verified through the separate chain activity view. Provisioned inboxes do not imply working social accounts. A prepared thesis is not a published post. Only reported successful posts with validated platform/author URLs become links.

Public requests are GET-only, have exact-origin CORS, reject unexpected query keys, and cap each list at 20 records. `hasMoreJobs` and `hasMorePublications` disclose truncation; full history pagination remains future work. Eight simultaneous requests per instance are allowed, with bounded SQL snapshots and RPC timeouts. Database loss returns 503 rather than an empty success. There is no response cache or distributed rate limit yet; capacity must be checked behind the production gateway before public release.

Acceptance: `test/public-operations.mjs` uses a real isolated PostgreSQL database and Fastify injection, plus a controlled chain fixture. Six scenarios cover role/column grants, private-data exclusion, isolation/truncation, outcome semantics, HTTP boundaries and database failure. `test-results/public-operations.json` records the checked scope. Actual Nova/Lyra Operations views are also connected to the local runtime database and registry.
